## 1\. 背景

| # | 課題 | 該当箇所 |
|---|---|---|
| 1 | 画像を 1 枚ずつしか保存できず、タグでまとめた写真を手元に残すのが大変 | — |

## 2\. 決定事項

| 項目 | 方針 |
|---|---|
| ダウンロードの対象 | **画面に表示している Snap**（絞り込み中のタグ＋無限スクロールで読み込んだ分）。「すべて」を選んでいるときも同じ |
| 上限 | **100 枚**。表示が 100 枚を超えているときは、上から（新しい順に）100 枚だけを Zip にする |
| Zip を作る場所 | Backend。Frontend は「どの Snap か」を ID の配列で送るだけ |
| API | `POST /chocolatier_api/snap/download/`、本文 `{ "ids": [12, 11, ...], "tag": "旅行" }`（「すべて」のときは `tag` を送らない） |
| Zip の中のフォルダ | 1 つだけ。タグ選択中はタグ名（`旅行/`）、「すべて」のときは `すべて/` |
| Zip のファイル名 | `旅行.zip` / `すべて.zip`。保存名は **Frontend で決める**（サーバーの `Content-Disposition` は、CORS の設定を足さないと JS から読めないため） |
| 中の画像の名前 | 保存時の名前のまま（`元の名前_yyyymmddHHMMSS.jpg`）。日時が付いているので重ならない |
| 圧縮 | `ZIP_STORED`（圧縮しない）。JPEG / PNG はもともと圧縮済みのため |
| 実ファイルが無い画像 | 飛ばして続ける（1 枚欠けていても他は渡す） |

### 「表示しているもの」にした理由

| 観点 | 内容 |
|---|---|
| 分かりやすさ | 画面で見えている写真がそのまま Zip に入る（見たまま） |
| 量の制御 | 読み込みは 12 件ずつなので、ユーザーがスクロールした分しか増えない。さらに 100 枚の上限で、Zip は最大でも約 500MB（1 枚 5MB × 100）に収まる |
| 「すべて」の扱い | タグごとにフォルダを分けると、タグなしの画像や複数タグの画像の置き場所が問題になる。表示分を 1 フォルダにまとめれば、この問題が起きない |

### ID を送る方式にした理由

- 画面に何が表示されているかは Frontend しか知らないため
- ただし ID は書き換えられる前提で扱い、Backend で必ず「自分の Snap か」を確かめる（他人の ID は黙って除外）

### 計画からの変更点

| 項目 | 計画 | 実際 | 理由 |
|---|---|---|---|
| フォルダ名 | タグ名をそのまま使う | 記号（\`\\ / : \* ? " < > | `）を` \_`に置き換え、前後の空白と`.`を取る。何も残らなければ`すべて\` |
| 実ファイルが全部ないとき | 記載なし（200 で空の Zip になる） | 404「ダウンロードできる画像がありません」 | 空の Zip を渡しても意味がないため |
| `BasicButton` | 変更なし | `disabled` を受け取れるようにした（押せないときは薄く表示） | ダウンロード中・0 件のときに押せなくするため |
| ボタンの位置と文字 | 絞り込みチップの横に「Zip でダウンロード」 | 1 段目の右端（新規作成の反対側）に、「「いぬ」の 12 枚を Zip でダウンロード」のように **タグ名と枚数** を入れる | 表示中の一覧が対象だと、UI でわかるようにするため。タグの下に別の段を作ると 3 段になって多いので、1 段目にまとめた |
| 100 枚を超えたとき | ダウンロード後にメッセージ | ダウンロード後のメッセージに加えて、**押す前** にもボタンの横に「表示中の 108 枚のうち、新しい 100 枚まで」と表示 | 押してから知るより、先にわかる方が親切なため |
| 件数のエラー（400） | 日本語のメッセージ | 英語（`Ensure this field has no more than 100 elements.` など） | DRF に `ListField` の件数エラーの日本語訳がないため。Frontend は 100 件までしか送らないので、通常は表示されない |
| テスト | A1〜A7 | A1〜A7 に加えて、実ファイルが消えている（1 枚・全部）、危ないタグ名の 3 つ | 変更点に合わせて追加 |
| 担当（M4・M5） | ユーザー | レビュアー | ユーザーの希望で変更 |

## 3\. 対応内容

### Backend

| ファイル | 内容 |
|---|---|
| `chocolatier_api/serializers.py` | `SnapZipDownloadSerializer` を追加。`ids`：`ListField(child=IntegerField(), min_length=1, max_length=100)`、`tag`：`CharField(required=False, max_length=30)` |
| `chocolatier_core/settings.py` | 上限値の定数 `MAX_ZIP_DOWNLOAD = 100` を追加 |
| `chocolatier_api/views.py` | `SnapZipDownload`（APIView, `post`）を追加。① 本文をチェック ② `Snap.objects.filter(user=request.user, id__in=ids).select_related('file')` で自分の Snap だけに絞る ③ 0 件なら 404 ④ `tempfile` の一時ファイルに `zipfile` で `<フォルダ名>/<画像名>` として書き込む ⑤ `FileResponse(as_attachment=True, filename='旅行.zip')` で返す（日本語のファイル名は Django が自動でエンコード） |
| `chocolatier_api/urls.py` | `snap/download/` を追加 |
| `chocolatier_api/tests.py` | 下の「確認項目」A1〜A7 |

### Frontend

| ファイル | 内容 |
|---|---|
| `pages/SnapshotPage/SnapshotPage.tsx` | 絞り込みチップの横に「Zip でダウンロード」ボタン。① `snaps` の先頭 100 件の ID を送る ② `client.post(..., { responseType: 'blob' })` で受け取る ③ `URL.createObjectURL` ＋ `<a download>` で保存させ、URL を破棄する ④ ダウンロード中はボタンを押せなくする ⑤ 100 件を超えていたら「新しい順に 100 枚をダウンロードしました」と表示 ⑥ 一覧が 0 件のときはボタンを押せなくする |
| `pages/SnapshotPage/SnapshotPage.css` | ボタンの配置 |
| `utils/validators.ts` | 定数 `MAX_ZIP_DOWNLOAD = 100` |
| `utils/apiError.ts` | `responseType: 'blob'` のときはエラーの本文も Blob で届くため、テキスト（JSON）に戻してから表示する処理 |

※ `client` を使うので、401 のときの自動 refresh と CSRF ヘッダーはそのまま効く
