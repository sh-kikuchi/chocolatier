## 0\. 考え方

### ■ 登場人物は 3 つ

| 登場人物 | 役割 | たとえると |
|---|---|---|
| **`react-easy-crop`**（`<Cropper>`） | ドラッグ・拡大縮小で「どこを切るか」を選ばせ、その範囲（ピクセル）を教えてくれる | 写真の上に置く、正方形の窓枠 |
| **canvas**（`cropImage.ts`） | 教えてもらった範囲を、実際に切り抜いて新しい画像にする | はさみ |
| **File** | 切り抜いた画像を、今までと同じ形で Backend に送る | 封筒に入れて送る |

`react-easy-crop` は **画像を加工しない**。「窓枠の位置」を数字で返すだけで、切るのは自分で書いた canvas の処理。

### ■ 全体の流れ

```
① FileInput で画像を選ぶ（拡張子だけチェック）
        ↓ sourceFile（元画像）
② ImageCropper で範囲を選ぶ → 「決定」
        ↓ cropImage(sourceFile, 範囲) で切り抜く
③ プレビュー表示（「画像を選び直す」で①に戻れる）
        ↓ file（切り抜き後）
④ 保存：サイズ（5MB）をチェックしてから、今までどおり FormData で送る
```

### ■ ブラウザの中で切り抜く理由

| 方法 | 良い点 | 悪い点 |
|---|---|---|
| **ブラウザで切り抜く（採用）** | 送るデータが小さくなる（1080px まで縮小）。Backend を変えなくてよい | ブラウザの機能（canvas）に頼る |
| サーバーで切り抜く（範囲を一緒に送る） | 元画像が残る | 大きな元画像をそのまま送る必要がある。Backend に Pillow の処理が増える |

## 1\. 切り抜く処理(src/utils/cropImage.ts)

### ■ 画像を読み込む（Promise に包む）

```ts
const loadImage = (src: string): Promise<HTMLImageElement> =>
  new Promise((resolve, reject) => {
    const image = new Image();
    image.onload = () => resolve(image);
    image.onerror = () => reject(new Error('画像を読み込めませんでした'));
    image.src = src;
  });
```

- `new Image()` は「読み込みが終わったら `onload` が呼ばれる」という古い形（コールバック）の API。
- `new Promise` で包むと、`await loadImage(url)` と書けるようになる。
- `resolve` / `reject` は Promise が引数で渡してくれる関数。**import は不要**（VSCode が `path` の `resolve` を自動で import してしまうことがあるので注意）。

### ■ canvas と getContext('2d')

```ts
const canvas = document.createElement('canvas');  // 紙を用意する
canvas.width = size;
canvas.height = size;
const context = canvas.getContext('2d');           // 紙に描くための道具箱を取り出す
if (!context) throw new Error('この環境では画像を加工できません');
```

- canvas は「真っ白な紙」。紙そのものには描く機能がないので、`getContext('2d')` で **描くための道具箱** を取り出す。
- `'2d'` は平面の描画用（画像を貼る・線を引く・文字を書く）。3D なら `'webgl'`。
- 道具箱を用意できないと `null` が返る。`if` で弾くと、その下では TypeScript が「null ではない」と判断してくれる。

### ■ drawImage の 9 個の引数

```ts
context.drawImage(
  image,                                    // 何を
  area.x, area.y, area.width, area.height,  // 元画像の「どこ」を（切り抜く範囲）
  0, 0, size, size                          // canvas の「どこ」に（この大きさで描く）
);
```

```
元画像（4000×3000）                  canvas（1080×1080）
┌───────────────────────┐
│     ┌─────────┐       │            ┌─────────┐
│     │ area    │       │  ──縮小──▶ │         │
│     │2000×2000│       │            │         │
│     └─────────┘       │            └─────────┘
└───────────────────────┘
  (area.x, area.y) から                (0, 0) から size×size に
```

- 「元画像のこの範囲」を「canvas のこの範囲」に描く。大きさが違えば自動で拡大・縮小される。
- `size = Math.min(Math.round(area.width), 1080)`：範囲が 1080px より大きければ縮小する。

### ■ canvas → Blob → File

```ts
const blob = await new Promise<Blob | null>((resolve) => canvas.toBlob(resolve, type, 0.9));
if (!blob) throw new Error('画像を作れませんでした');
return new File([blob], getOutputName(file.name), { type });
```

| 型 | 中身 | 今回の使い道 |
|---|---|---|
| `Blob` | 名前のないデータのかたまり | `toBlob` が返す。Zip ダウンロード（改修案件5）で受け取ったのも Blob |
| `File` | **名前の付いた Blob** | FormData で送るときにファイル名が必要なので、File にする |

- `toBlob` もコールバックの形なので、`loadImage` と同じく Promise に包む。
- `0.9` は jpeg / webp の画質（0〜1）。png では無視される。

### ■ gif が静止画（png）になる理由

- canvas は「1 枚の絵」しか持てないので、アニメーション gif を描くと **1 コマ目だけ** になる。
- canvas は gif として書き出せない（`toBlob` が対応しているのは png / jpeg / webp）ので、png にする。
- ファイル名も `anime.gif` → `anime.png` に付け替える（`getOutputName`）。

## 2\. 範囲を選ぶ部品(ImageCropper.tsx)

### ■ 値は外が持つ（制御されたコンポーネント）

```tsx
<Cropper
  image={imageUrl}
  crop={crop}                          // 位置 { x, y }：この部品が持つ
  zoom={zoom}                          // 拡大率：この部品が持つ
  aspect={1}                           // 1:1
  onCropChange={setCrop}               // 動かしたら知らせてもらう
  onZoomChange={setZoom}
  onCropComplete={handleCropComplete}  // 動かし終わったら、切り抜く範囲（ピクセル）を受け取る
/>
```

- `TagInput` の `tags` / `onChangeTags` と同じ考え方。値は外が持ち、変わったら関数で知らせてもらう。
- `onCropComplete` の引数は `(割合, ピクセル)` の 2 つ。canvas で使うのはピクセルの方。
- 親に「決定」を知らせる props は `onConfirm` にした。`onCropComplete` にすると `<Cropper>` の props と名前がかぶって紛らわしいため。

### ■ 親に高さが必要

```css
.cropArea {
  position: relative;
  width: 100%;
  height: 300px;
}
```

- `<Cropper>` は中で `position: absolute` を使い、**親いっぱい** に広がる。
- 親に高さがないと 0px になり、何も表示されない。

## 3\. 一時的な URL と StrictMode

`<Cropper>` や `<img>` に File を見せるには、`URL.createObjectURL(file)` で一時的な URL を付け、使い終わったら `URL.revokeObjectURL(url)` で破棄する。

**NG（以前の書き方）**

```tsx
const imageUrl = useMemo(() => URL.createObjectURL(file), [file]);
useEffect(() => {
  return () => URL.revokeObjectURL(imageUrl);
}, [imageUrl]);
```

**OK（今の書き方）**

```tsx
const [imageUrl, setImageUrl] = useState<string | undefined>(undefined);
useEffect(() => {
  const url = URL.createObjectURL(file);  // 作る
  setImageUrl(url);
  return () => URL.revokeObjectURL(url);  // 破棄する
}, [file]);
```

- `index.tsx` の `<React.StrictMode>` は、開発中だけ useEffect を **「実行 → 後片付け → 実行」と 2 回** 動かす（後片付けし忘れのバグを見つけるため）。
- NG の形だと、お試しの後片付けで URL が破棄されたあと、`useMemo` は作り直さない → **破棄済みの URL** が残って画像が表示されない。
- **作るのも破棄するのも同じ useEffect の中** に書けば、2 回目の実行で作り直される。
- 本番のビルドでは 2 回実行されないので NG の形でも表示されるが、開発中に気づけないので OK の形にそろえる。`SnapshotPage` の `previewUrl` も同じ形に直した。

## 4\. 投稿画面(SnapshotPage.tsx)

### ■ 画像の状態を 2 つに分ける

| 状態 | 中身 | 画面 |
|---|---|---|
| `sourceFile` も `file` もない | 未選択 | `FileInput` |
| `sourceFile` だけある | 選んだが、まだ切り抜いていない | `ImageCropper` |
| `file` がある | 切り抜き済み | プレビュー＋「画像を選び直す」 |

- 送るのは `file`（切り抜き後）だけ。
- 「閉じる」「選び直す」では **両方を戻す**（`resetImage`）。片方だけ戻すと、古い画像が残る。

### ■ チェックするタイミング

| チェック | いつ | 理由 |
|---|---|---|
| 拡張子 | 選んだとき（`FileInput`：`validateImageExtension`） | 切り抜いても形式は選び直せない |
| サイズ（5MB） | 保存の直前（`SnapshotPage`：`validateImageSize`） | 8MB の写真でも、切り抜き・縮小すれば 5MB 以下になって投稿できる |
| 中身が本当に画像か | Backend（Pillow） | 今までどおり |

「**その時点で判断できることだけを、その時点でチェックする**」。以前は 1 つの関数（`validateImageFile`）で両方を見ていたので、2 つに分けた。Frontend のチェックはあくまで早く気づかせるためで、本当の守りは Backend（改修案件2）。

## 5\. テスト手順

**自動テスト**（`frontend` フォルダで）

```
npm test
```

- `src/__tests__/utils/validators.test.ts`：拡張子・サイズのチェックと、切り抜いた画像の名前・形式（gif → png など）
- canvas の描画は Jest（jsdom）では動かないので、切り抜き自体はブラウザで確認する

**ブラウザ確認**

1. playground の「image cropper」で、画像を選ぶ → 動かす → 「決定」。正方形の画像とファイル名・形式・サイズが出る
2. 投稿画面の「新規作成」で、選ぶ → トリミング → 保存。一覧に正方形の画像が増える
3. gif を選ぶと、形式が `image/png`・ファイル名が `.png` になる
4. bmp を選ぶと、選んだ時点でエラー

## 6\. つまずきやすいところ

| 症状 | 原因 | 対処 |
|---|---|---|
| 枠（グリッド）は出るのに画像が出ない | StrictMode で、破棄済みの URL が残っている | URL を作る処理も useEffect の中に入れる（[3 章](#3-一時的な-url-と-strictmode)） |
| `<Cropper>` が何も表示されない | 親に高さがない | 親に `position: relative` と `height` を付ける |
| `import { resolve } from 'path'` が勝手に増える | VSCode の自動 import | 消す。Promise の `resolve` は import 不要 |
| `context.drawImage` で「null かもしれない」と怒られる | `getContext` は null を返すことがある | `if (!context) throw ...` で弾く |
| 中身を書く前のファイルでエラー（isolatedModules） | import も export もないファイルは使えない設定 | 仮で `export {};` を置き、export を書いたら消す |
| 切り抜いた画像の画質が落ちる | jpeg / webp は `toBlob` の画質（0.9）で圧縮される | 必要なら値を上げる（ファイルサイズとのかね合い） |
