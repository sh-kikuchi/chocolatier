## 1. はじめに

### 1-1. 環境を作る
- セットアップと起動の手順は、リポジトリ直下の `README.md`（「セットアップと起動」）。
- 必要なもの：Windows 11・Python 3.13・Node.js 24・Microsoft Edge。
- VS Code は、リポジトリの `.vscode/settings.json` で次の設定になっている。
  - Python は `backend/venv` を使う
  - TypeScript は `frontend/node_modules` の版（4.9.5）を使う
  - bat ファイルは Shift_JIS で開く・保存する（UTF-8 だと cmd で文字化けする）

### 1-2. フォルダの地図
```
chocolatier/
  backend/                    … Django（API・管理画面・画像の配信）
    chocolatier_core/         … 設定（settings.py）と URL の入口
    chocolatier_api/          … アプリ本体（views/・serializers/・services/・models.py・signals.py・tests/）
  frontend/                   … React（画面）
    src/pages/                … 画面
    src/components/           … 部品（commons：共通、snap：スナップ用、playground：部品の見本）
    src/api/client.ts         … API の呼び出し口
    src/utils/                … チェック・エラー表示・切り抜き
  docs/                       … このドキュメント
  start_chocolatier.bat など  … 起動・終了・ショートカット作成
```
詳しくは [アーキテクチャ](../02_設計/01_アーキテクチャ.md) と [01_Djangoの全体像.md](01_Djangoの全体像.md)。

### 1-3. よく使うコマンド
| すること | コマンド（`backend` は venv を有効にしてから：`venv\Scripts\activate`） |
|---|---|
| Backend を起動 | `cd backend` → `python manage.py runserver` |
| Frontend を起動 | `cd frontend` → `npm start` |
| Backend のテスト | `cd backend` → `python manage.py test chocolatier_api` |
| Frontend のテスト | `cd frontend` → `npm test`（一度だけ流すなら `set CI=true && npm test`） |
| 型チェック | `cd frontend` → `npx tsc --noEmit -p .` |
| モデルを変えたあと | `python manage.py makemigrations chocolatier_api` → `python manage.py migrate` |
| 設定のチェック | `python manage.py check` |
| 管理者を作る | `python manage.py createsuperuser` |

## 2. 開発の進め方

### 2-1. 新しい機能を作る順番
1. **改修事案を作る**：`docs/04_改修事案/_template.md` をコピーして計画（背景・決定事項・対応内容・マイルストーン・確認項目）を書き、`04_改修事案/00_一覧.md` の一覧に足す
2. **Backend をデータに近い層から作る**：models.py → マイグレーション → admin.py → serializers/ → services/ → views/ → urls.py（理由は [01_Djangoの全体像.md の「開発の順番」](01_Djangoの全体像.md#5-開発の順番)）
3. **Backend のテストを書く**：`backend/chocolatier_api/tests/test_*.py`。とくに「他人のデータが見えない・触れない」ことは必ず確かめる
4. **Frontend を作る**：部品（components/）→ 画面（pages/）。部品は playground で単体で試せるようにする
5. **ドキュメントを直す**：02_設計（API 定義・DB・機能一覧・画面一覧・シーケンス図）と、この開発ガイドの関係する記事。改修事案に結果と「計画からの変更点」を書く

### 2-2. 守ること
| 項目 | 決まり | 理由・記事 |
|---|---|---|
| 持ち主 | スナップ・画像を探すときは、必ず `filter(user=request.user)` の範囲で探す。他人の ID は 404 | 存在を知らせない（[03_認証.md](03_認証.md)） |
| 投稿者 | 送られた `user` は使わず、`request.user` を入れる | なりすまし防止 |
| 上限値 | `settings.py` に置き、Frontend の `validators.ts` にも同じ値を書く | ずれるとテストが失敗する（[06_入力チェック.md](06_入力チェック.md)） |
| 層の役割 | View は流れだけ。変換・チェックは Serializer、ファイルなどの作業は Service | [01_Djangoの全体像.md](01_Djangoの全体像.md) |
| 後片付け | 削除のときの後片付け（実ファイルなど）は `signals.py` に書く | API 以外（管理画面など）から消しても動くように |
| HTTP メソッド | 使わないメソッドは開けない（`http_method_names`） | [05_スナップAPIと画像.md](05_スナップAPIと画像.md) |
| API の呼び方 | Frontend は必ず `api/client.ts` の `client` を使う | Cookie・CSRF・自動 refresh（[02_CORS.md](02_CORS.md)） |
| 画像の一時 URL | `createObjectURL` は、作るのも破棄するのも同じ `useEffect` の中で | StrictMode 対策（[10_画像トリミング.md](10_画像トリミング.md)） |

### 2-3. 書き方
- **コメントは処理のブロックごとに、番号付き（①②③…）で書く**。関数の先頭の docstring にまとめない。
  ```python
  # ① 受け取った値をチェックする
  serializer = SnapZipDownloadSerializer(data=request.data)
  serializer.is_valid(raise_exception=True)

  # ② 自分の Snap だけを取得する
  snaps = Snap.objects.filter(user=request.user, id__in=ids)
  ```
- ファイルの先頭には、`# ===` で囲んだ見出しコメントで「何のファイルか」を書く。
- import には、何のために使うかを短く添える。
- ドキュメントの担当は「ユーザー」「レビュアー」のように役割名で書く。
- コミットメッセージは英語で `接頭辞:内容_yyyymmdd`（→ [11_Gitとリポジトリ.md](11_Gitとリポジトリ.md)）。

## 4. テストの場所
| 場所 | 中身 |
|---|---|
| `backend/chocolatier_api/tests/test_auth.py` | Cookie 認証・権限・サインアップ |
| `backend/chocolatier_api/tests/test_snap.py` | 入力チェック・タグ・ページング |
| `backend/chocolatier_api/tests/test_zip.py` | Zip ダウンロード |
| `backend/chocolatier_api/tests/test_services.py` | services/ を API を通さずに |
| `backend/chocolatier_api/tests/test_fixes.py` | 改修案件08（PUT・画像の配信・削除の後片付け・トランザクション・メールの重複・上限値の同期） |
| `backend/chocolatier_api/tests/base.py` | 共通の部品（テスト用の設定・画像の作り方・alice と bob） |
| `frontend/src/__tests__/App.test.tsx` | Welcome 画面 |
| `frontend/src/__tests__/utils/validators.test.ts` | チェック関数と、切り抜いた画像の名前・形式 |
| `frontend/src/__tests__/components/commons/GuestRoute/GuestRoute.test.tsx` | ログイン中・未ログインでの移動 |

- **テストは本体と分けて置く**：Backend は `chocolatier_api/tests/`、Frontend は `src/__tests__/` の中に、`src/` と同じフォルダの形で置く（例：`src/utils/validators.ts` のテストは `src/__tests__/utils/validators.test.ts`）。CRA は `__tests__` の中の `*.test.ts(x)` を自動で見つける。`src/setupTests.ts` だけは `src/` の直下に置く（CRA の決まり）。
- Backend のテストは、テスト用の DB と一時フォルダを使うので、`db.sqlite3` と `media/` は変わらない。
- 2026-11-19 時点で、Backend 68 件・Frontend 22 件がすべて通る。
