# 管理画面（Django admin）

- 最終更新：2026-11-19（今の `admin.py` に合わせて書き直した）
- 根拠：`backend/chocolatier_api/admin.py`、`backend/chocolatier_api/signals.py`

## 1. 入り方
1. 管理者（スーパーユーザー）を作る（最初に 1 回。手順はリポジトリ直下の `README.md` のセットアップ ①）
   ```cmd
   cd backend
   venv\Scripts\activate
   python manage.py createsuperuser
   ```
2. Backend を起動して `http://localhost:8000/admin/` を開き、作った管理者でログインする。
- 管理画面は **Django 標準のセッション認証** で動く（アプリの Cookie の JWT とは別）。
- 入れるのは `is_staff`（スタッフ権限）がある利用者だけ。`createsuperuser` で作った利用者は `is_staff=True`、API（`/chocolatier_api/signup/`）で作った利用者は `is_staff=False`。

## 2. 管理できるもの
| モデル | 一覧の列 | 検索 | 絞り込み | そのほか |
|---|---|---|---|---|
| 利用者（`UserAdmin`） | ID・ユーザー名・メール・スタッフ・有効 | ユーザー名・メール | スタッフ・有効・スーパーユーザー | Django 標準の `UserAdmin` を継承（パスワードはハッシュで保存）。ID 順 |
| ファイル（`FileAdmin`） | ID・名前・パス・作成・更新日時 | 名前・パス | ― | 作成・更新日時は編集不可 |
| スナップ（`SnapAdmin`） | ID・利用者・ファイル・コメント・タグ・作成・更新日時 | コメント・ユーザー名・ファイル名 | 利用者・ファイル・タグ | タグは左右 2 つのリストで選ぶ（`filter_horizontal`）。タグはまとめて取得（N+1 対策） |
| タグ（`TagAdmin`） | ID・名前・Snap 数・作成日時 | 名前 | ― | Snap 数で並べ替えられる（`annotate(Count('snaps'))`） |

## 3. 管理画面から消したときの後片付け（改修案件08）
| 消したもの | いっしょに消えるもの |
|---|---|
| スナップ | その画像（File の行と `media/uploads/` の実ファイル）、どのスナップにも付いていないタグ |
| ファイル | それを使っているスナップ（CASCADE）と実ファイル |
| 利用者 | その人のスナップ（CASCADE）→ 画像・使われなくなったタグ |

- 後片付けは `signals.py`（削除のあとに Django が自動で呼ぶ関数）で行うので、API から消したときと同じ動きになる。
- 以前は後片付けが API の中にしかなく、管理画面で消すと実ファイルが残っていた。

## 4. 書き方のポイント（admin.py）
```python
@admin.register(Tag)
class TagAdmin(admin.ModelAdmin):
    list_display = ('id', 'name', 'snap_count', 'created_at')

    # ① 一覧で使うデータの取り方：タグごとの Snap の数を SQL で数えて足す
    def get_queryset(self, request):
        return super().get_queryset(request).annotate(snap_count=Count('snaps'))

    # ② 一覧の「Snap数」の列（ordering で列の見出しから並べ替えできる）
    @admin.display(description='Snap数', ordering='snap_count')
    def snap_count(self, obj):
        return obj.snap_count
```
| 設定 | 意味 |
|---|---|
| `list_display` | 一覧に出す列（メソッド名も書ける） |
| `search_fields` | 検索の対象。`user__username` のように `__` で関連先も指定できる |
| `list_filter` | 右側の絞り込み |
| `readonly_fields` | 編集できない項目（自動で入る日時など） |
| `filter_horizontal` | 多対多を左右 2 つのリストで選ぶ形にする |
| `get_queryset` | 一覧のデータの取り方（`prefetch_related`・`annotate` で SQL の回数を減らす） |

## 5. 注意
- 管理画面で利用者を作るときは、API の登録と違って **メールアドレスの重複チェックがない**（Django 標準のフォームのため）。
- 管理画面でスナップの画像を差し替える機能はない（ファイルの行の「パス」を書き換えても、実ファイルは動かない）。
